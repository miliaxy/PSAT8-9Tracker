# PSAT Pathway planning contract

This repository is public. Never place a real student's name, results, schedule, account details, answer keys, or private Supabase records in tracked source or demo fixtures. Use fictional data in public examples.

For private daily planning, the governing workflow is:

1. Load the student's current Supabase evidence before proposing work: target score, test date, latest section scores, practice-test trends, drill accuracy and difficulty, mistakes, concept state, Khan progress evidence, schedule constraints, and days remaining.
2. Build or refresh the end-to-end score roadmap. Identify the active phase, weekly milestone, section checkpoints, official skills that remain unlearned, and learned skills that have not reached the Easy/Medium mastery gate.
3. Every non-reading assignment must state which official PSAT 8/9 skill and active milestone it advances. Reject locally reasonable work that does not advance the roadmap.
4. Use the College Board PSAT 8/9 framework and Question Bank as the scope authority. A prep provider's unit outline is not the syllabus. Map individual Khan Academy, IXL, or book items to the official skill before assigning them; never assign an entire vendor unit merely because it appears in sequence.
5. Separate concept learning, review, drilling, mistake research, and practice tests. Do not drill a concept that is still unlearned or in progress.
6. Use only official PSAT 8/9 drill questions unless the parent explicitly approves an exception. Exclude active practice-test questions, track used question IDs, and avoid repeats.
7. Give every drill an exact question count, exact difficulty mix, PSAT 8/9 solving time, direct resource or packet link, and required mistake review. Keep Hard locked until at least 95% recent Easy/Medium accuracy across meaningful evidence.
8. Include independent reading on study days and a short mixed spiral of previously learned skills on normal weekdays. Respect the current family schedule; weekend patterns are defaults, not reasons to ignore a parent's explicit change.
9. State the evidence-based reason, success criterion, and next recalculation signal for each plan. Say when evidence is missing.
10. Save private plans as drafts only. A parent reviews, edits, and explicitly publishes them. Never publish automatically.

Before finishing a roadmap or plan change, run the project type check, lint, and GitHub Pages build. Preserve unrelated worktree changes.
